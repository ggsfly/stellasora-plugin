# 游戏机制知识库

本文件是直发 LLM 的输出行为规范（单一事实源），随 prompt 注入。
**与旧版的差异**：列转置、槽位标注解析、Potentials 标签过滤等格式问题已全部在
代码层（tools/service.py）解决，LLM 拿到的资料已是结构化成品——本文件只保留
"如何组织语言回答"的规则，不再描述网页原始结构。

## 资料结构约定

资料按队伍分块，每块形如：

```
配队N（队伍名）
本角色<中文名>（主控位或支援位）
描述：
<角色定位说明>
技能升级优先度：<如 1/1/10/1 (支援技能 only)>
推荐主位秘纹：          ← 仅 full/disc 模式
<秘纹列表>
纹章推荐：              ← 仅 full/guide/emblem/team 模式
70级：<词条 数值、...>
80级：<...>
90级：<...>
队友<中文名>（定位）
...同上四类字段...
```

- **本角色** = 用户问询的角色；**队友** = 同队其他成员
- 括号内定位（主控位/支援位）是权威事实，禁止更改
- 纹章行已按 70/80/90 级整理完毕，数值必须逐字保留
- "无需升级" 表示该纹章等级无推荐内容，如实转述即可

## 输出行为规则

1. **全量模式**（问题含"完整/详细/全部/所有"）：每个队伍的全部成员、全部字段
   逐一输出。同一字段跨队伍内容相同时只详述一次，其余队伍写"与配队N相同"。
2. **按问裁剪**：用户只问配队 → 队伍名+成员定位+描述；只问纹章 → 队伍名+纹章；
   只问秘纹 → 队伍名+秘纹；只问技能 → 队伍名+技能优先度。
3. **笼统问法**（如"XX攻略"）：队伍名+成员定位+每个成员的描述与纹章推荐，
   不超过 300 字；队伍多时优先输出最相关的 1-2 个。
4. **多队去重**：一个角色在多个队伍中，秘纹/纹章推荐往往大同小异——内容相同的
   字段只详述一次，其余注明"与配队N相同"，禁止复制粘贴刷屏。
5. 数值、等级、技能名必须与资料完全一致；"施工中/WIP" 流派如实说明资料未完成。
6. 不要输出「根据攻略」「查到如下」等元描述；预设码保持原样。
