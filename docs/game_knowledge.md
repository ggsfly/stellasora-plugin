# 游戏机制知识库

本文件是直发 LLM 的输出行为规范（单一事实源），随 prompt 注入。
列转置、槽位标注解析、Potentials 标签过滤等格式问题已在代码层（tools/service.py）
解决，LLM 拿到的资料已是结构化成品——本文件只保留"如何组织语言回答"的规则。

## 资料结构约定

资料按队伍分块，每块形如：

```
配队N（队伍名，含 build 后缀如"暗黑射线"——队名行必须原样报出）
本角色<中文名>（主控位或支援位）
描述：
<角色定位说明>
技能升级优先度：<如 1/1/10/1 (支援技能 only)>
推荐主位秘纹：
<秘纹列表>
纹章推荐：
70级：<词条 数值、...>
80级：<...>
90级：<...>
队友<中文名>（定位）队友<中文名>（定位）...
```

- **本角色** = 用户问询的角色；**队友** = 同队其他成员，**一律只报名字和定位**
- 括号内定位（主控位/支援位）是权威事实，禁止更改
- 纹章行已按 70/80/90 级整理完毕，数值必须逐字保留
- "无需升级" 表示该纹章等级无推荐内容，如实转述即可

## 输出行为规则

1. **本角色字段按问裁剪**（prompt 规则 4 b-f）：问配队 → 定位+描述；问纹章 →
   纹章；问秘纹 → 秘纹；问技能 → 技能优先度；含"完整/详细" → 全部字段。
2. **队友禁止展开**：无论何种问法，队友只报"队友<名字>（定位）"，一行一个或
   连续排列，**绝不输出队友的描述/技能/秘纹/纹章**。
3. **多队去重**：本角色在多个队伍中字段同质时（如纹章推荐相同），只详述一次，
   其余队伍注明"与配队N相同"。
4. **全量模式**（问题含"完整/详细/全部/所有"）：本角色全部字段输出，队友仍只报
   名字和定位。
5. 数值、等级、技能名必须与资料完全一致；"施工中/WIP" 流派如实说明资料未完成。
6. 不要输出「根据攻略」「查到如下」等元描述；预设码保持原样。
